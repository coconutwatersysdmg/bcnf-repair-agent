# 阶段结果：离线实验验收（2026-10-21）

## 结论边界

本阶段只验证数据生成、实验矩阵、独立评估、统计汇总和三种检查后端的一致性。模型臂使用 `SIMULATED` 客户端，不是真实大模型结果，不能据此声称 B1、B2 或 B3 优于其他方法，也不能作为论文效果表的最终数据。

本阶段没有发出真实模型请求，API 费用为 0 元。

## 基线验证

- 环境：Windows，CPython 3.12.14。
- 命令：`python -m unittest discover -s tests -v`。
- 结果：29 项测试全部通过。
- 核心覆盖：30 个随机 FD 模式、每个模式 64 个候选子集，共 1,920 个候选子集与独立朴素定义核对。

## 最终离线矩阵

数据生成命令：

```powershell
python -m repair_agent generate --out data/phase0e13_20261021 --count 300 --entities 13 --seed 20261021 --split pilot
```

运行命令：

```powershell
python -m repair_agent run --data data/phase0e13_20261021/public.jsonl --out runs/phase0e13_offline_20261021 --mode simulate --arms D0,D1,B0,B1,B2,B3,B3_truncate,B3_random --repeats 3
python -m repair_agent evaluate --run runs/phase0e13_offline_20261021 --truth data/phase0e13_20261021/private_truth.jsonl
python -m repair_agent analyze --run runs/phase0e13_offline_20261021
python -m repair_agent replay --run runs/phase0e13_offline_20261021
```

数据由 3 类结构、5 类场景和 C0/C1 两条轨道构成，每个单元格 10 个任务，共 300 个任务。每个实验臂重复 3 次，共生成并评估 7,200 条结果。

回放共检查 10,800 个候选状态，`general`、`bcnf_index` 与 `incremental` 三种检查后端全部一致，未出现非 BCNF 跳过项。

## 口径修正记录

首轮使用默认 `entities=20`，D1 的 900 条结果全部因超过 18 条记录而得到 `REFERENCE_SIZE_LIMIT`。第二轮改成 `entities=18` 后，非 clean 场景会追加脏记录，D1 仍有 720/900 条超过限制。

最终使用 `entities=13`。生成器最坏情况下增加 `floor(0.30×13)+1=4` 条记录，总数最多 17，因此所有任务都落在 D1 的穷举上限内。前两轮保留在本地用于审计，但不得混入论文结果。

该问题说明正式实验应区分：

1. 用于 D1 最优参照的小规模任务，强制最终记录总数不超过 18；
2. 用于可扩展性和真实模型评测的常规任务，不运行 D1，避免把“参照算法不适用”误计为失败。
